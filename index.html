Scenario 實際作用


        

          
            

              Scenario
              API 回傳行為
              主要用途
            

          
          
            

              normal
              回傳合法 payload，包含 total，數值會微幅變動。
              測試一般正常資料讀取。
            

            

              no-total
              回傳合法 payload，但不包含 total。
              測試主專案是否會用 office + residential 自動加總。
            

            

              http-500
              回傳 HTTP 500。
              測試 HTTP 錯誤時的 fallback。
            

            

              invalid-json
              回傳故意損壞的 JSON 字串。
              測試 JSON parse error 時的 fallback。
            

            

              invalid-schema
              回傳合法 JSON，但欄位缺漏或型別錯誤。
              測試 validation error 時的 fallback。
            

            

              timeout
              延遲回應，預設至少 10 秒。
              測試 timeout fallback。
            

            

              custom
              回傳 Payload Editor 中按下 Use Edited Payload 後儲存的內容。
              測試真實廠商 API 格式或特殊資料格式。
            

          
        


        
Query String 覆蓋規則


        

          如果 URL 有指定 ?scenario=xxx，會優先使用 URL 指定的 scenario。
          如果 URL 沒有指定 scenario，才會使用 UI 下拉選單目前選擇的 scenario。
        


        
http://127.0.0.1:3101/api/energy
http://127.0.0.1:3101/api/energy?scenario=http-500
http://127.0.0.1:3101/api/energy?scenario=custom
