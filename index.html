情境說明

          

            
              

                情境
                行為
                用途
              

            
            
              

                normal
                回傳正常的 energy payload。
                基本成功路徑測試。
              

              

                no-total
                移除 payload 中的 total 節點。
                測試 aggregate 資料缺失時的 client fallback。
              

              

                http-500
                回傳 HTTP 500。
                驗證錯誤處理流程。
              

              

                invalid-json
                回傳格式損壞的 JSON。
                測試 JSON parser 失敗情境。
              

              

                invalid-schema
                回傳欄位型別錯誤或欄位缺漏的 JSON。
                測試 schema 驗證失敗情境。
              

              

                timeout
                延遲回應以模擬 timeout 行為。
                驗證 timeout 處理流程。
              

              

                custom
                回傳目前 Payload 編輯器中的內容。
                測試自訂 API 回應內容。
              

            
          


          
Query String 覆蓋規則

          

            請求可透過 ?scenario=... 覆蓋目前 UI 的情境設定；若未指定，則使用 UI 目前選擇的情境。
          


          
http://127.0.0.1:3101/api/energy
http://127.0.0.1:3101/api/energy?scenario=http-500
http://127.0.0.1:3101/api/energy?scenario=custom

Modbus 對 API 橋接

          

            此模式在 R2 仍為 placeholder，會在 Modbus TCP 模擬器穩定後再實作橋接行為。
          

        


        

          
橋接概念

          
Modbus Register Table
        -> Mapping Rules
        -> HTTP API Payload
        -> Frontend / BMS API Client

        


        

          
後續規劃

          
    
            
  • 從 Modbus register table 讀取資料。
    • 
            
  • 將 register 對應到 JSON path。
    • 
            
  • 產生 HTTP API response payload。
    • 
            
  • 提供固定的 BMS energy mapping 預設。
    • 
            
  • 延伸成通用 JSON mapper。
    •
